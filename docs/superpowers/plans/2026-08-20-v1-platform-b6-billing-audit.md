> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `zhijin-billing-audit` 模块实现用量统计与审计（**按 DDD 四层直接新建**）：`usage_record`（token 用量落账）+ `audit_log`（操作留痕），聊天流程接入用量记录，管理操作接入审计，提供租户用量查询接口。

## 关键决策

- **DDD 原生**：`zhijin-billing-audit` 模块直接按 `interfaces/application/domain/infrastructure` 建，无迁移。
- **用量记录**：`usage_record` 每次模型调用一行（chat 流程）；V1 记录 tenant/app/session/model/latency_ms，token 字段（prompt/completion/total）为 0，计划 C 返回真实 token 后填充。
- **审计记录**：`audit_log` 每次管理操作一行（actor/action/target/detail）；V1 覆盖：应用创建/编辑/删除/发布、API Key 生成/吊销。
- **接入方式（依赖倒置）**：`zhijin-chat`/`zhijin-app` 依赖 `billing-audit` 的**端口接口**（`UsageRecorder`/`AuditRecorder` fun interface，放 domain），infra 实现；避免循环依赖。参考 B5 的 `ApiKeyResolver` 模式。
- **查询接口**：`GET /api/usage/summary`（管理端，租户用量汇总：按天/按应用）。审计查询 `GET /api/audit-logs`（V1 基础分页）。

```sql
-- 用量与审计（V1 基础）
CREATE TABLE IF NOT EXISTS usage_record (
    id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id         BIGINT       NOT NULL,
    app_id            BIGINT       NOT NULL,
    session_id        BIGINT,
    model             VARCHAR(128) NOT NULL DEFAULT '',
    prompt_tokens     INT          NOT NULL DEFAULT 0,   -- 计划 C 返回真实 token 后填充
    completion_tokens INT          NOT NULL DEFAULT 0,
    total_tokens      INT          NOT NULL DEFAULT 0,
    latency_ms        INT          NOT NULL DEFAULT 0,
    create_time       TIMESTAMP    NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_usage_tenant_time ON usage_record (tenant_id, create_time);
CREATE INDEX IF NOT EXISTS idx_usage_app ON usage_record (tenant_id, app_id);

CREATE TABLE IF NOT EXISTS audit_log (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id   BIGINT       NOT NULL,
    user_id     BIGINT,
    username    VARCHAR(64)  NOT NULL DEFAULT '',
    action      VARCHAR(64)  NOT NULL,        -- APP_CREATE / APP_UPDATE / APP_DELETE / APP_PUBLISH / API_KEY_GENERATE / API_KEY_REVOKE
    target_type VARCHAR(32)  NOT NULL DEFAULT '',  -- app / api_key / ...
    target_id   BIGINT,
    detail      TEXT         NOT NULL DEFAULT '',
    create_time TIMESTAMP    NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_audit_tenant_time ON audit_log (tenant_id, create_time);
```

- [ ] **Step 1: infrastructure 持久化**

`infrastructure/persistence/UsageRecordRecord.kt`（贫血，`var id`，toDomain/from）+ `UsageRecordMapper.kt`（`@Mapper`，`BaseMapper<UsageRecordRecord>`）+ `UsageRepositoryImpl.kt`：
```kotlin
@Repository
class UsageRepositoryImpl(private val mapper: UsageRecordMapper) : UsageRepository {
    override fun save(record: UsageRecord): UsageRecord {
        val rec = UsageRecordRecord.from(record)
        mapper.insert(rec)
        return rec.toDomain()
    }
    override fun summarizeByApp(tenantId: Long, start: LocalDateTime?, end: LocalDateTime?): List<UsageSummary> {
        // 简化：按 app 分组统计调用次数与 token 总量
        val qw = QueryWrapper<UsageRecordRecord>().eq("tenant_id", tenantId)
        if (start != null) qw.ge("create_time", start)
        if (end != null) qw.le("create_time", end)
        return mapper.selectList(qw).groupBy { it.appId }.map { (appId, rows) ->
            UsageSummary(appId = appId!!, totalCalls = rows.size, totalTokens = rows.sumOf { it.totalTokens ?: 0 })
        }
    }
}
```
> 说明：汇总用内存分组（V1 量小可接受）；量大后换 SQL group by。

`AuditLogRecord.kt`/`AuditLogMapper.kt`/`AuditRepositoryImpl.kt` 同理，`page()` 在实现内部用 `selectPage` 并转换为 domain `PageResult<AuditLog>`（P5：domain 接口不暴露 MyBatis-Plus 类型）。

**@MapperScan**：`MybatisPlusConfig` 需加 `"com.zhijin.billingaudit.mapper"`（P3：Mapper 在顶层 `com.zhijin.billingaudit.mapper`，与 @MapperScan 路径一致；必要修改）。
